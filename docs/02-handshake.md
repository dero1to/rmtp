# 02. ハンドシェイク詳解

> 対応ソースコード: `pkg/handshake/handshake.go`

## ハンドシェイクとは

RTMPの通信は、TCP接続確立後に必ず **ハンドシェイク** から始まる。
クライアントとサーバーがバージョン情報とランダムデータを交換し、
通信の準備が整ったことを確認するための手順。

ハンドシェイクが完了するまで、チャンクやメッセージは一切送れない。

## ハンドシェイクの目的

1. **プロトコルバージョンの合意**: 互いにサポートするRTMPバージョンを確認
2. **RTT（往復遅延時間）の推定**: タイムスタンプの差分でネットワーク遅延を推定
3. **接続の正当性確認**: ランダムデータのエコーバックにより、データが壊れていないことを確認

## 6つのパケット

ハンドシェイクでは6つのパケットがやりとりされる:

```
クライアント                          サーバー
    │                                   │
    │── C0 (1バイト) ─────────────────>│
    │── C1 (1536バイト) ──────────────>│
    │                                   │
    │<─────────────────── S0 (1バイト) ─│
    │<──────────────── S1 (1536バイト) ─│
    │<──────────────── S2 (1536バイト) ─│
    │                                   │
    │── C2 (1536バイト) ──────────────>│
    │                                   │
    │    ★ ハンドシェイク完了 ★          │
```

## 各パケットの構造

### C0 / S0 （1バイト）

RTMPプロトコルのバージョン番号。

```
+----------+
| version  |
| (1 byte) |
+----------+
```

| 値 | 意味 |
|---|---|
| `0x03` | RTMP（プレーン、暗号化なし）← **本実装で使用** |
| `0x06` | RTMPE（Adobeの独自暗号化） |

本実装ではバージョン3のみをサポート。

**対応するソースコード:**

```go
// pkg/handshake/handshake.go
const RTMPVersion = 3

// サーバー側: C0を読み取り、バージョンを確認
c0 := make([]byte, 1)
io.ReadFull(rw, c0)
if c0[0] != RTMPVersion {
    return fmt.Errorf("サポートされていないバージョン: %d", c0[0])
}
```

### C1 / S1 （1536バイト）

タイムスタンプとランダムデータを含むパケット。

```
+---------------+---------------+----------------------------+
| timestamp     | zero          | random data                |
| (4 bytes)     | (4 bytes)     | (1528 bytes)               |
+---------------+---------------+----------------------------+
  ビッグエンディアン  常に0x00000000   crypto/rand で生成
```

| フィールド | サイズ | 説明 |
|---|---|---|
| timestamp | 4バイト | 送信側の基準時刻（ミリ秒）。RTT推定に使う |
| zero | 4バイト | 将来の拡張用予約領域（常に0） |
| random data | 1528バイト | 任意のバイト列。C2/S2でエコーバックされる |

**なぜ1536バイトなのか?**

RTMPの仕様書で定められた固定値。1536 = 4 + 4 + 1528 という構造で、
1528バイトのランダムデータは接続の正当性確認に十分なエントロピーを提供する。

**対応するソースコード:**

```go
// pkg/handshake/handshake.go - C1の生成
c1 := make([]byte, HandshakeSize) // 1536バイト
timestamp := uint32(time.Now().UnixMilli())
binary.BigEndian.PutUint32(c1[0:4], timestamp) // タイムスタンプ
binary.BigEndian.PutUint32(c1[4:8], 0)         // ゼロ
rand.Read(c1[8:])                               // ランダムデータ
```

### C2 / S2 （1536バイト）

相手のC1/S1のエコーバック。

```
+---------------+---------------+----------------------------+
| peer timestamp| timestamp2    | random data echo           |
| (4 bytes)     | (4 bytes)     | (1528 bytes)               |
+---------------+---------------+----------------------------+
  C1/S1からコピー   送信時の時刻     C1/S1のランダムデータをそのまま
```

| フィールド | サイズ | 説明 |
|---|---|---|
| peer timestamp | 4バイト | 相手のC1/S1から受け取ったタイムスタンプ |
| timestamp2 | 4バイト | C2/S2を送信する時点のタイムスタンプ |
| random data echo | 1528バイト | 相手のC1/S1のランダムデータをそのまま返す |

**エコーバックの意味:**

サーバーがS2でC1のランダムデータをそのまま返すことで、
クライアントは「自分が送ったデータが正しく届いた」ことを確認できる。
逆にC2でS1のデータを返すことで、サーバー側も同様の確認ができる。

**対応するソースコード:**

```go
// pkg/handshake/handshake.go - S2の生成（C1のエコーバック）
s2 := make([]byte, HandshakeSize)
copy(s2, c1) // C1の内容をそのままコピー
binary.BigEndian.PutUint32(s2[4:8], uint32(time.Now().UnixMilli())) // timestamp2だけ更新
```

## ハンドシェイクの合計データ量

```
C0:  1 バイト
C1:  1536 バイト
S0:  1 バイト
S1:  1536 バイト
S2:  1536 バイト
C2:  1536 バイト
─────────────────
合計: 6146 バイト（約6KB）
```

## 実装上のポイント

### 1. C0+C1の同時送信

多くの実装では、C0とC1を別々に送らず、まとめて1回のwrite()で送信する。
これによりTCPのラウンドトリップを減らし、ハンドシェイクを高速化する。

### 2. S0+S1+S2の同時送信

同様に、サーバーもS0, S1, S2を1回のwrite()で送ることが多い。
C1を受信した時点でS2（C1のエコー）も生成できるため、
3つのパケットをまとめて送信できる。

### 3. 検証の省略

仕様上はC2のランダムデータがS1と一致するか検証すべきだが、
多くの実装（本実装を含む）ではこの検証を省略している。
理由: TCPが順序保証と誤り検出を提供するため、追加の検証は冗長。

### 4. バージョン合意の重要性

C0/S0でバージョンを確認することで、例えばRTMPE（暗号化版）を
要求するクライアントに対して非対応を早期に通知できる。
