# 01. RTMPプロトコルの全体像

## RTMPとは

**RTMP (Real-Time Messaging Protocol)** は、Macromedia（後にAdobeが買収）が開発した
リアルタイム通信プロトコル。もともとはFlash Playerとサーバー間で
音声・映像・データをやりとりするために設計された。

Flash Playerは2020年末にサポートが終了したが、RTMPは **ライブ配信のデファクトスタンダード** として
現在も広く使われている。OBS Studio、Twitch、YouTube Live、ニコニコ生放送など、
ほとんどのライブ配信サービスがRTMPに対応している。

## なぜRTMPが生き残っているのか

1. **低遅延**: TCP上で動作しつつも、1〜3秒程度の低遅延を実現
2. **広いエコシステム**: OBSをはじめとする多くの配信ソフトが対応
3. **シンプルな配信モデル**: publish/playの概念がわかりやすい
4. **CDNとの相性**: 多くのCDNがRTMP ingestをサポート

## プロトコルスタック

RTMPは以下のレイヤーで構成される。下から上に向かって読むとわかりやすい。

```
┌─────────────────────────────────────────────────────────┐
│                   アプリケーション層                       │
│                                                          │
│  コマンド: connect, createStream, publish, play          │
│  データ:   onMetaData, @setDataFrame                     │
│  メディア: 音声(AAC/MP3), 映像(H.264)                    │
├─────────────────────────────────────────────────────────┤
│                   メッセージ層                            │
│                                                          │
│  メッセージタイプで種別を区別する                          │
│  TypeID 1-6:  プロトコル制御                              │
│  TypeID 8:    音声                                       │
│  TypeID 9:    映像                                       │
│  TypeID 18:   データ（メタデータ）                        │
│  TypeID 20:   コマンド（AMF0エンコード）                  │
├─────────────────────────────────────────────────────────┤
│                チャンクストリーム層                        │
│                                                          │
│  メッセージを小さなチャンクに分割して多重化する            │
│  ヘッダ圧縮（Type 0〜3）で通信量を削減                    │
│  デフォルトチャンクサイズ: 128バイト（通常4096に変更）      │
├─────────────────────────────────────────────────────────┤
│                  ハンドシェイク                            │
│                                                          │
│  C0/S0: バージョン合意 (1バイト)                          │
│  C1/S1: タイムスタンプ + ランダムデータ (1536バイト)       │
│  C2/S2: エコーバック (1536バイト)                         │
├─────────────────────────────────────────────────────────┤
│                      TCP                                  │
│                                                          │
│  デフォルトポート: 1935                                   │
│  信頼性のある順序付きバイトストリーム                      │
└─────────────────────────────────────────────────────────┘
```

## RTMP URL の構造

```
rtmp://hostname:port/app/streamkey
│       │         │    │     │
│       │         │    │     └── ストリームキー（配信の識別子）
│       │         │    └── アプリケーション名（通常 "live"）
│       │         └── ポート番号（デフォルト: 1935）
│       └── ホスト名またはIPアドレス
└── プロトコル（rtmp / rtmps）
```

例:
- `rtmp://localhost:1935/live/mystream` → app="live", streamkey="mystream"
- `rtmp://ingest.twitch.tv/app/live_xxxxx` → app="app", streamkey="live_xxxxx"

## 通信の全体フロー

### 配信（publish）の場合

```
配信者(OBS等)                             サーバー
    │                                       │
    │  ① TCP 3-way handshake               │
    │<─────────────────────────────────────>│
    │                                       │
    │  ② RTMP ハンドシェイク                │
    │  C0+C1 ─────────────────────────────> │
    │  <───────────────────────── S0+S1+S2  │
    │  C2 ─────────────────────────────────>│
    │                                       │
    │  ③ connect("live")                    │  AMF0コマンド
    │─────────────────────────────────────> │
    │  <───────── Window Ack Size (2.5MB)   │  プロトコル制御
    │  <─────── Set Peer Bandwidth (2.5MB)  │  プロトコル制御
    │  <───────── Set Chunk Size (4096)     │  プロトコル制御
    │  <──────────────── _result (成功)      │  AMF0コマンド
    │                                       │
    │  ④ releaseStream("streamkey")         │  （省略可能）
    │─────────────────────────────────────> │
    │  ⑤ FCPublish("streamkey")             │  （省略可能）
    │─────────────────────────────────────> │
    │  ⑥ createStream                       │
    │─────────────────────────────────────> │
    │  <──────── _result (streamID=1)       │
    │                                       │
    │  ⑦ publish("streamkey", "live")       │
    │─────────────────────────────────────> │
    │  <──────────── Stream Begin (event)   │  ユーザー制御
    │  <──── onStatus("Publish.Start")      │  AMF0コマンド
    │                                       │
    │  ⑧ @setDataFrame + onMetaData         │  メタデータ
    │─────────────────────────────────────> │
    │  ⑨ 音声データ (TypeID=8) ──────────> │  連続送信
    │  ⑩ 映像データ (TypeID=9) ──────────> │  連続送信
    │  ...繰り返し...                        │
    │                                       │
    │  ⑪ deleteStream / FCUnpublish         │  配信終了
    │─────────────────────────────────────> │
```

### 視聴（play）の場合

```
視聴者                                    サーバー
    │                                       │
    │  (TCP接続 + ハンドシェイク)             │
    │<─────────────────────────────────────>│
    │  connect("live")                      │
    │─────────────────────────────────────> │
    │  <──────────────── _result(成功)       │
    │  createStream                         │
    │─────────────────────────────────────> │
    │  <──────── _result(streamID=1)        │
    │                                       │
    │  play("streamkey")                    │  視聴開始
    │─────────────────────────────────────> │
    │  <──────────── Stream Begin           │
    │  <──── onStatus("Play.Start")         │
    │                                       │
    │  <──────── onMetaData (キャッシュ)     │  途中参加対応
    │  <──── 音声ヘッダ (AAC Seq Header)    │  途中参加対応
    │  <──── 映像ヘッダ (AVC Seq Header)    │  途中参加対応
    │                                       │
    │  <──── 音声データ (リアルタイム中継)   │
    │  <──── 映像データ (リアルタイム中継)   │
    │  ...繰り返し...                        │
```

## RTMPの派生プロトコル

| プロトコル | 説明 |
|---|---|
| RTMP | プレーンな非暗号化プロトコル（本実装） |
| RTMPS | TLS/SSLで暗号化されたRTMP（ポート443） |
| RTMPE | Adobeの独自暗号化（現在は非推奨） |
| RTMPT | HTTPトンネリング版RTMP（ファイアウォール回避用） |
| RTMFP | UDP版（P2P対応、Flash専用） |

本実装は **RTMP（プレーン版）** に対応している。
