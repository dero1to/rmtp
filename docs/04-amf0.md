# 04. AMF0 シリアライズ形式詳解

> 対応ソースコード: `pkg/amf0/amf0.go`

## AMF0 とは

**AMF0 (Action Message Format version 0)** は、Adobe（旧Macromedia）が策定した
バイナリシリアライズ形式。JSONのバイナリ版と考えるとわかりやすい。

RTMPでは、コマンドメッセージ（connect, publish, playなど）のパラメータを
やりとりする際にAMF0が使われる。

## AMF0 と JSON の比較

```
JSON:  {"app": "live", "type": "nonprivate"}
       → 人間が読めるテキスト形式（約40バイト）

AMF0:  03 00 03 61 70 70 02 00 04 6C 69 76 65 ...
       → バイナリ形式（約30バイト）、パース処理が高速
```

AMF0は:
- **型情報付き**: 各値の先頭にデータ型マーカー（1バイト）が付く
- **ビッグエンディアン**: 数値はネットワークバイトオーダー
- **スキーマ不要**: 自己記述的なフォーマット

## データ型マーカー

各値の先頭1バイトがデータ型を示す。デコーダはこのバイトを見て
後続のデータをどう読むか判断する。

| マーカー | 値 | 型名 | 説明 |
|---|---|---|---|
| `0x00` | Number | 数値 | IEEE 754 倍精度浮動小数点数（8バイト） |
| `0x01` | Boolean | 真偽値 | 1バイト（0=false, 1=true） |
| `0x02` | String | 文字列 | 2バイト長プレフィックス + UTF-8文字列 |
| `0x03` | Object | オブジェクト | キー・バリューの集合 |
| `0x05` | Null | null | マーカーのみ（データ部なし） |
| `0x08` | ECMAArray | 連想配列 | 4バイト要素数 + キー・バリュー |
| `0x09` | ObjectEnd | オブジェクト終端 | 0x00 0x00 0x09 の3バイト |

## 各データ型の詳細

### Number型（0x00）

```
+--------+-------------------------------+
| 0x00   | IEEE 754 double (8 bytes, BE) |
+--------+-------------------------------+
  1バイト          8バイト
```

例: 数値 `1.0` のエンコード:
```
00 3F F0 00 00 00 00 00 00
│  └──────────────────────── IEEE 754 倍精度 1.0 のビットパターン
└── マーカー: Number
```

RTMPではトランザクションIDやストリームIDなど、整数値もNumber型で送る。
例えばストリームID `1` は `float64(1.0)` としてエンコードされる。

### Boolean型（0x01）

```
+--------+-------+
| 0x01   | value |
+--------+-------+
  1バイト  1バイト

value: 0x00 = false, それ以外 = true
```

### String型（0x02）

```
+--------+------------------+------------------+
| 0x02   | length (2B, BE)  | UTF-8 data       |
+--------+------------------+------------------+
  1バイト    2バイト            可変長
```

例: 文字列 `"connect"` のエンコード:
```
02 00 07 63 6F 6E 6E 65 63 74
│  └──┘  └────────────────────── "connect" のUTF-8バイト列
│  長さ=7
└── マーカー: String
```

**文字列長の制限**: 2バイト（uint16）で長さを表すため、最大 **65535バイト**。
それ以上の文字列にはLong String（マーカー0x0C）が必要だが、
RTMPの実用上は通常のString型で十分。

### Object型（0x03）

```
+--------+──────────────────────────────+──────────+
| 0x03   | key-value pairs (繰り返し)    | 終端マーカー |
+--------+──────────────────────────────+──────────+

各 key-value:
  +------------------+------------------+──────────────────+
  | key length (2B)  | key (UTF-8)      | value (AMF0値)   |
  +------------------+------------------+──────────────────+
  ※ キーにはマーカーが付かない（常に文字列なので）
  ※ バリューにはマーカーが付く（型が不定なので）

終端マーカー:
  +------+------+------+
  | 0x00 | 0x00 | 0x09 |
  +------+------+------+
  空文字列キー + ObjectEnd
```

例: `{"app": "live"}` のエンコード:
```
03                          ← Object開始マーカー
  00 03 61 70 70            ← キー "app" (長さ3 + "app")
  02 00 04 6C 69 76 65      ← バリュー: String "live"
00 00 09                    ← Object終端
```

**キーの順序保持について:**

RTMPの仕様上、オブジェクトのキー順序は保持されるべき。
本実装では `Object` 構造体にキー配列 `Keys []string` を持たせて
挿入順序を保持している。

```go
type Object struct {
    Keys   []string         // キーの挿入順序を保持
    Values map[string]Value // キーから値へのマッピング
}
```

### Null型（0x05）

```
+--------+
| 0x05   |
+--------+
  1バイト（マーカーのみ、データ部なし）
```

コマンドメッセージで「パラメータなし」を表す際に使う。
例えばcreateStreamコマンドでは `null` が送られる。

### ECMAArray型（0x08）

```
+--------+------------------+──────────────────────────+──────────+
| 0x08   | count (4B, BE)   | key-value pairs          | 終端マーカー |
+--------+------------------+──────────────────────────+──────────+
```

Object型とほぼ同じだが、先頭に4バイトの要素数が付く。
ただし要素数は **参考値** であり、実際の要素数と異なる場合もある。
終端は常にObjectEndマーカー（0x00 0x00 0x09）で判定する。

主な用途: onMetaDataイベントのメタ情報（duration, width, heightなど）。

## RTMPでの使われ方

### コマンドメッセージの構造

RTMPのコマンドメッセージ（TypeID=20）は、複数のAMF0値が連続して格納される:

```
値1: String コマンド名     例: "connect", "publish", "_result"
値2: Number トランザクションID 例: 1.0, 2.0
値3〜: コマンド固有のパラメータ（Object, Null, Stringなど）
```

### 具体例: connectコマンド

```
値1: String "connect"
値2: Number 1.0
値3: Object {
       app: "live",
       type: "nonprivate",
       flashVer: "FMLE/3.0",
       tcUrl: "rtmp://localhost/live"
     }
```

バイナリ表現:
```
02 00 07 "connect"                  ← String "connect"
00 3F F0 00 00 00 00 00 00         ← Number 1.0
03                                  ← Object開始
  00 03 "app" 02 00 04 "live"      ←   app: "live"
  00 04 "type" 02 00 0A "nonprivate" ← type: "nonprivate"
  ...
00 00 09                           ← Object終端
```

### 具体例: _result（connect応答）

```
値1: String "_result"
値2: Number 1.0                    ← connectのトランザクションIDと対応
値3: Object {                      ← サーバーのプロパティ
       fmsVer: "FMS/3,0,1,123",
       capabilities: 31.0
     }
値4: Object {                      ← 接続結果の情報
       level: "status",
       code: "NetConnection.Connect.Success",
       description: "Connection succeeded."
     }
```

### 具体例: publishコマンド

```
値1: String "publish"
値2: Number 0.0                    ← トランザクションID（応答不要なので0）
値3: Null                          ← コマンドオブジェクト（なし）
値4: String "streamkey"            ← ストリームキー
値5: String "live"                 ← 配信タイプ
```

### 具体例: onMetaData

```
値1: String "@setDataFrame"        ← データフレーム設定
値2: String "onMetaData"           ← メタデータイベント名
値3: ECMAArray {                   ← メタデータ本体
       duration: 0.0,
       width: 1920.0,
       height: 1080.0,
       videodatarate: 2500.0,
       framerate: 30.0,
       videocodecid: 7.0,          ← 7 = H.264/AVC
       audiodatarate: 128.0,
       audiosamplerate: 44100.0,
       audiocodecid: 10.0,         ← 10 = AAC
       stereo: true
     }
```

## テストの説明

`pkg/amf0/amf0_test.go` では以下をテスト:

1. **TestEncodeDecodeNumber**: 数値型の往復テスト（0, 1, -1, 3.14, ...）
2. **TestEncodeDecodeString**: 文字列型の往復テスト（空文字列、ASCII、日本語）
3. **TestEncodeDecodeBoolean**: 真偽値型の往復テスト
4. **TestEncodeDecodeNull**: null型の往復テスト
5. **TestEncodeDecodeObject**: オブジェクト型の往復テスト（キー数・値の確認）
6. **TestEncodeDecodeMultipleValues**: connectコマンドを模した複数値の連続エンコード/デコード
